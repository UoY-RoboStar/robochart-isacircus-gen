# Renaming in the HOL-CSP output: correctness checks and a shorter notation (23 Nov 2026)

How the generator prints renamings is described in `docs/CONTROLLER_MODULE_STATUS.md`, Section 5.1. In short:
every non-empty renaming is the relational renaming `P ⟦⟦R⟧⟧` (`Relational_Renaming R (=) P`, RC_HOL-CSP,
`Relational_Renaming.thy`), with R printed by `parseRelRenaming` (circusM2T_HOLCSP.egl) as one lambda term: one
disjunct per pair `rn_a = old ∧ rn_b = new`, existentially bound variables for missing channel arguments, and a
last disjunct "rn_a outside the domain ∧ rn_b = rn_a".

## 2. A shorter notation (branch `renaming-short`, NOT merged)

### 2.1 What

Library (AG-dev branch `renaming-short`, fd44ca3, worktree `~/Git/RoboChart-Deadlock-HOLCSP-AG-dev-renaming-short`):
`Renaming_Notation.thy` in RC_HOL-CSP, imported by `RoboChart_Library` (so the generated theories, which import
only RoboChart_Library, are unchanged in their imports):

| Notation | Meaning | Old clause |
|---|---|---|
| `ren_ev a b` | a becomes b | `rn_a = a ∧ rn_b = b` |
| `ren_chan c d` | c v becomes d v | `∃v. rn_a = c v ∧ rn_b = d v` |
| `ren_chan2 c d` | c v w becomes d v w | two shared variables |
| `ren_chan_ev c b` | every c x becomes b | `∃x. rn_a = c x ∧ rn_b = b` (untyped trigger projection) |
| `ren_proj c d` | every c x v becomes d v | `∃x v. rn_a = c x v ∧ rn_b = d v` (typed trigger projection) |
| `ren_ev_chan a d` | a becomes every d v | `∃v. rn_a = a ∧ rn_b = d v` (one-to-all) |
| `ren_else [R1, ..., Rn]` | union of the Ri; an event no Ri relates is unchanged | the last "identity" disjunct |

Laws (simp rules; proofs need not unfold the definitions): `ren_*_iff`, `Domainp_ren_*`, `ren_else_iff`,
`ren_else_image(_in, _out)`, `Relational_Renaming_ren_else_write0` with the corollaries `_in` (an event in the
domain becomes the external choice of its images) and `_out` (unchanged). Checked on an abstract datatype in the
scratch session (parameterised prefix keeps its value; one-to-many gives the external choice; outside unchanged).

Generator (branch `renaming-short`, 58cc646): `parseRelRenamingShort` in both HOL-CSP templates prints

```
(Behaviour ...
	 ⟦⟦ren_else
	    [ren_ev share share,
	     ren_ev_chan share setR_x_C2_composite_c2,
	     ren_chan set_x_C2_composite_c2 setL_x_C2_composite_c2]⟧⟧)
```

one pair per line; a pair of any other shape is printed as before as a lambda term inside the list (none
occurred).

`deadlock_free'`, the normalisation and reduction rule sets: they work on the Trans and Trans-core equations,
which contain no renaming; the Trans-core theories of the branch are token for token those of f585967 and the
ITP proof theories built from them are byte-identical to those proved in COMPOSITE_RELEASE_TEST Section 15. The
AG-dev proof theories import older generated files and are not affected; theories that copy a generated
relation (`R10_def`, `Rint`) would, for newly generated files, use the simp rules above instead of the lambda.

### 2.4 Recommendation

Not for this release. The gain is readability only (no change in time or memory, the meaning is proved equal),
and it adds a dependency: theories generated by the new plugin need an RC_HOL-CSP that contains
`Renaming_Notation`; with an older library every generated theory fails at the first renaming. If it is taken
later, the library must be released together with the plugin:

1. merge AG-dev `renaming-short` (only `Renaming_Notation.thy`, `ROOT`, `RoboChart_Library.thy`) into master and
   rebuild every session on RC_HOL-CSP;
2. publish that RC_HOL-CSP where the users of the plugin get it (today the generated theories import
   `RC_HOL-CSP.RoboChart_Library` from AG-dev, registered in `~/Isabelle/Isabelle2025-2/ROOTS`; for other users the
   library would have to be published, e.g. with a version tag, or as part of the ITP repository's
   `RC_HOL-CSP`), and state in the plugin's release notes which library version the output needs;
3. merge the generator branch `renaming-short` and release the plugin.
Alternative without a library dependency: the generator prints the seven definitions and the laws it needs at
the top of each theory (larger files; two generated theories imported together would clash).
