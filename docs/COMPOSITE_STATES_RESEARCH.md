What the existing models do and do not cover:

- **Cross-level transitions: none**, in any model. They are not part of RoboChart: the validator has
  the rule `noInterlevelTransition` ("The source and target of a transition should belong to the same
  container"), and the scoping does not even resolve the name of a node of another container (checked
  on the model in `composite-tests/rejected/`). So the generator needs no case for them. A transition
  whose source is the composite state itself (from the boundary) is an ordinary transition of the outer
  container.
- Every feature asked about occurs somewhere, but **never in a small model, and for the more
  interesting ones without CSP-M at hand**: a during action on a composite state only in TransportSwarm
  (no CSP-M) and hvc `Transition_system` (CSP-M, but the model is a module with four controllers); an
  exit action on a composite state only in TransportSwarm, Firefighter `Mission`, Exploration
  `Avoiding` (no CSP-M); nesting only in hvc `ClosedLoop` (CSP-M, large), Firefighter, Exploration, RAD.
- Most of these models are timed (`since`, `sinceEntry`, `#C`, `wait`) or call operations, or are
  probabilistic. The HOL-CSP generator supports none of these, so they cannot serve as test inputs for
  it as they are.
- A composite state without any state (only junctions and a final state) exists (AutonomousVehicle).
  The validator requires "at least one state or final state".

## 3. The generator today

### 3.1 What happens on a composite state

`RC2Z.eol` does not finish on a model with a composite state (generator issue S). The path:
Rule 29 `stateful` → Rule 29-2 `machineBody` → Rule 40 `ncBehaviour(stm)` → Rule 41
`ncCoreBehaviour(stm)` → Rule 52 `composeNodes` → for a state with `nodes.size() > 0`, Rule 60
`createCompositeStateAsActionParas()`.

Rule 60 (lines 6032-6140) is a draft:

1. line 6069: `self.actions.selectOne(a | a.instanceOf(RC!DuringAction)).action` without a test; fails
   when the state has no during action (as `MakePlan`);
2. line 6070: `ncbehaviour(self)`; no such operation (Rule 40 is `ncBehaviour`), and Rule 40 as written
   cannot be called on a state (see 3.2);
3. step 3: `createRunAction(...)` does not exist;
4. step 8: the prefix is built with `"enter_" + self.FQN()`; it must be `entered_`;
5. the synchronisation set of `Behaviour` uses `"interrupt_" + nc(self).FQN()` (marked TBC); it must be
   the interrupt of the composite state itself, `"interrupt_" + self.FQN()`, which is at the same time
   the container interrupt of the inner level (Rule 41 renames the inner node interrupts to
   `"interrupt_" + nc.FQN()`, and Rule 53 uses that name in the interrupt branch of Trans);
6. `Behaviour` is built with the plain `createParallelAction` and name sets; the write synchronisation
   (Definition C.2.2) is not applied, although `createMetaParallelAction` implements it;
7. the final hiding `\ (enteredSS ∪ {terminate})` of `Behaviour` is missing;
8. `enteredSS(self)` returns strings, and the loop of step 1 calls `e.name` on them;
9. `"During_" + self.FQN().createCallAction()` applies `createCallAction` to the FQN only (operator
   precedence).

In Rule 52 the branch for a composite state does not add `"Inactive_" + nd.FQN()` to
`ndActionNameSet`, so the composite node would be missing from `composeNodes`.

### 3.2 What assumes a single node container

### 3.3 What can be reused as it is

- Rule 41 `ncCoreBehaviour(nc)`, Rule 53 `createTransitionsAsActionPara`, Rule 53-1 (Trans core),
  Rules 54 and 55 (one transition), `flowevts`, `enterSS`, `enteredSS`, `transSync`, `vtguards`: written
  for a `NodeContainer`, with all names built from `nc.FQN()`. `RC!Node FQN()` has a case for a node
  inside a composite node (`A_S_M`). So the inner level gets its own events `enter_A_S_M`,
  `entered_A_S_M`, `interrupt_A_S_M`, `interrupt_S_M`, `exit_S_M`, `exited_S_M`, `internal__S_M`
  without any change. In the CSP-M `exit` and `exited` are global events used at every level and hidden
  per level; here they are different events per level, which changes nothing in the meaning (the inner
  ones are hidden inside `Behaviour` in both).
- The interrupt branch of Trans (Rule 53, `interrupt_<nc> → exit → exited → terminate`): it exists in
  every flat Trans and is the way out of a composite state.
- A transition whose source or target is a composite state: Rules 54 and 55 use only the FQN of the
  node and the events of the container; nothing depends on the kind of state.
- Rules 46-50 `vars`: Rule 48 already descends into `node.nodes` and `node.transitions`.
- `createMetaParallelAction` (Definition C.2.2) has all four name sets (pr, pw, qr, qw), so it can
  build the two-sided write synchronisation of `Behaviour`.
- The frame of Rule 60 (`Inactive`, `Activation`, `Termination`, `Active`, `Exiting`) is copied from
  Rule 59 and is right, including `exited` under SSTOP.
- `createStateActionAsCircusAction` for entry, during and exit actions; it returns Skip when the
  state has no action of that kind, so Rule 60 needs no test for a missing during action if it uses
  this operation only (the failing line 6069 computes a name set, which is replaced, see 4.2).
- Metamodel: `HideAction`, `ParallelAction`, `InterleaveAction`, `RenameAction`, `CallAction` with an
  expression list exist. No metamodel change is needed; `RUN` can be a `CallAction` named `RUN` with a
  set expression as argument.
- Templates: printers for hiding, parallel, interleaving and renaming exist in all three templates
  (never exercised on interleaving; see 4.3).

## 4. What has to be added or changed

### 4.1 One decision first: node identifiers and trigger channels per level

The CSP-M declares, in the module of every container, its own `NIDS`, `internal__ : NIDS` and
`e__ : NIDS.InOut...` for every event; Rule 40 of each level renames `e__.x` to `e`. Two ways to have
this in one Isabelle theory:

- **(A) per container**, as the CSP-M: `NIDS_<nc>` and `internal__<nc>` as now; the trigger channels of
  a state container get the container in their name (`e__in_<S>`), those of the machine keep `e__in`.
  Each level is then literally an instance of the flat construction, with its own type of node
  identifiers, which is what the proofs want (one protocol instance and one family per level). Cost:
  one more set of trigger channels per composite state; `renameTriggerEventsPairL/R` and `tevent_str`
  take the container into account.
- **(B) one `NIDS` for the whole machine** (all nodes of all levels) and the trigger channels declared
  once. Fewer declarations and the templates' single `NID_name` stays, but every `Trans_<nc>` is then
  defined on node identifiers of other levels too (vacuous cases in every proof by cases on the node),
  and it departs from the modules of the CSP-M.

Recommendation: (A). For a flat machine both give exactly the present output. To be decided by Fang.

## 5. Draft translation scheme for a composite state

Notation: S a composite state, C its container (the machine or a state); names as the generator
builds them (`enter_S` stands for `"enter_" + S.FQN()`, `exit_C` for `"exit_" + C.FQN()`). `SSTOP △ P`
is what the CSP-M writes `share__choice(P)`. Reference: the node `MakePlan` in the CSP-M of
Adaptation_Plan (lines 299-760).

### 5.1 The two levels

    ncCoreBehaviour_S = (composeNodes_S)[interrupt renaming of S's nodes]
                          ⟦ flowevts(S) ∪ transSync(S) ∪ {terminate}, write synchronisation (C.2.2) ⟧
                        (enter_i0_S → Trans_S(NID_i0_S))                              -- Rule 41, nc = S
    ncBehaviour_S     = (ncCoreBehaviour_S \ (enterSS(S) ∪ {exit_S, exited_S} ∪ range internal__S))
                          [trigger renaming of S]                                     -- Rule 40, nc = S

with `flowevts(S) = enterSS(S) ∪ {exit_S, exited_S, interrupt_S}`. These are the flat rules applied to
the state. `composeNodes_S` composes the nodes of S on `{share, terminate}`; a node of S that is itself
composite is treated by the same scheme (recursion; test c6).

The outer level is unchanged: S is one node of `composeNodes_C`, and Rule 41 for C renames
`interrupt_S` to the events of the transitions from S and to `interrupt_C`.

### 5.2 The node of S

    Inactive_S    = SSTOP △ (Activation_S □ Termination_S)
    Activation_S  = enter_S → Active_S
    Termination_S = terminate → Skip
    Active_S      = Entry_S ; Behaviour_S ; Exiting_S
    Exiting_S     = (SSTOP △ (exit_C → Skip)) ; Exit_S ; (SSTOP △ (exited_C → Skip)) ; Inactive_S

This is the frame of a simple state (Rule 59). Only `Behaviour_S` differs; for a simple state it is
`entered_S → ((During action ; SSTOP) △ (interrupt_S → Skip))`.

    Behaviour_S = ( ncBehaviour_S   [share ↦ share and every setR_x] [set_x ↦ setL_x]
                      ⟦ enteredSS(S) ∪ {interrupt_S, terminate, share} ∪ {setL_x} ∪ {setR_x} ⟧
                    During_S        [share ↦ share and every setL_x] [set_x ↦ setR_x]
                  ) [setL_x ↦ set_x] [setR_x ↦ set_x]
                  \ (enteredSS(S) ∪ {terminate})

    During_S    = (SSTOP △ (□ e ∈ enteredSS(S) → Skip)) ;
                  entered_S → ( (RUN(enteredSS(S)) ||| (During action of S ; SSTOP))
                                △ (interrupt_S → (SSTOP △ (terminate → Skip))) )

To generate `Behaviour_S`: `createMetaParallelAction(S, ncBehaviour_S, pr, pw, cs, qr, qw, During_S)`
with `cs = enteredSS(S) ∪ {interrupt_S, terminate}`, then the hiding.

The sets of variables x: in the CSP-M of Adaptation_Plan the lists on both sides contain all seven
variables of the machine, although `MakePlan` has no during action (so qw = ∅ by Definition C.2.2
would give no setR at all), and the inner level (Rule 41) lists six. So the CSP-M generator does not
compute these sets as the manual's `vars` of each side. With more events than necessary in a
synchronisation set and in a saturating renaming the process is the same as long as neither side can
perform the extra events, so both readings can be right; which sets to generate has to be fixed
against the generator source and c2, c3 **[compare]**.

### 5.3 Entering

1. `enter_S`, synchronised with `Trans_C` (outer level).
2. `Entry_S`: the entry action of S; its reads and writes are events of the outer level (write
   synchronisation of the outer Rule 41, as for a simple state with an entry action).
3. `Behaviour_S` starts: `enter_i0_S` and the first inner transition run inside `ncBehaviour_S`
   (hidden). `During_S` waits (under SSTOP) for ONE inner `entered` event, synchronised with the inner
   node, then offers `entered_S`.
4. After `entered_S`, which is not synchronised at the outer level (Rule 41) and hidden at the level
   of C, the during action of S runs once, interleaved with `RUN(enteredSS(S))` so that inner states
   can keep being entered, and ends in SSTOP.

So `entered_S` comes after the entry action of the first inner state, not directly after `enter_S`.
Consequence for the proofs: between `enter_S` and `entered_S` the node performs inner (hidden) steps
and, if the first inner transition or inner entry action reads or writes, visible events.

### 5.4 Exiting

A transition from S (trigger or `internal__C.NID_S`) or the interrupt of C appears to the node, through
the interrupt renaming of the outer level, as `interrupt_S`. Inside `Behaviour_S` it is a joint event
of `During_S`, of `Trans_S` (its interrupt branch, offered only at the head of Trans, i.e. between
inner transitions) and of the inner node that is active (after its `entered`). Then:

1. the active inner node and `Trans_S`: `exit_S`, the inner node's exit action, `exited_S` (hidden by
   Rule 40 of S; an inner composite node first does this same sequence one level down);
2. `Trans_S`: `terminate`, with all inner nodes (inactive by then) and with `During_S`, which has been
   waiting in `SSTOP △ (terminate → Skip)`; all three sides of `Behaviour_S` end; this `terminate` is
   hidden by `Behaviour_S`, so it is not the `terminate` of the outer level, although it has the same
   name;
3. `Exiting_S`: `exit_C`, the exit action of S, `exited_C`, each `exit`/`exited` with `Trans_C`.

An inner final state does not end S: reaching it makes `Trans_S` offer `terminate`, which `During_S`
accepts only after `interrupt_S` (test c5).

### 5.5 Why exited is under SSTOP

`(SSTOP △ (exited → Skip)) ; Inactive` (generator change of 6 Nov 2026, as the CSP-M): when an inner
state is left by an inner transition, S stays active and its during action may write between the inner
`exit` and `exited`. That write is a `share` step for the inner side (the renaming of `ncBehaviour_S`
in `Behaviour_S`), and every inner node must take part in it, also the one between `exit` and
`exited`. In general: every position of a node, of Trans and of `During` is under SSTOP (or
`share__choice`), so that a write by the other side of any enclosing parallel composition is never
refused. The new paragraphs keep this: both waiting points of `During_S` are under SSTOP.

### 5.6 Points to check against the CSP-M of the test models

1. c1: the three CSP-M processes `Behaviour`, `During` and the frame agree with 5.2 for a second model
   (so far read from Adaptation_Plan only).
2. c2, c3: the variable lists of the two write synchronisations (5.2).
3. c3: `RUN(enteredSS) ||| (during ; SStop)`: the during action is not restarted when an inner state
   is entered.
4. c4: the same event on an inner and on a boundary transition; a self-transition of the composite
   state.
5. c5: `enteredSS` of a composite state whose only inner node besides the initial junction is a final
   state. The generator's `enteredSS` selects `RC!State`, and `Final` is a subtype of `State` in the
   RoboChart metamodel (`robochart.ecore`), so the `entered` of a final state is included, as in the
   CSP-M of Adaptation_Plan (`f0::entered` in `enteredSS`).
6. c6: the names and the hiding at three levels; `terminate` hidden once per composite state.
7. Divergence: a composite state whose inner machine can loop on hidden events only (inner transitions
   without trigger between states, e.g. two inner states connected by unguarded untriggered transitions)
   diverges after the hiding of `Behaviour_S`. None of the test models does this. In HOL-CSP a divergent
   process is ⊥ and is not deadlock free; FDR reports it with a divergence check.
